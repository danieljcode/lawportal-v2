# Templates and forms

How a form is written, the rules that keep it safe, and how the 39 court forms are generated.

There are two kinds of form:

- **The 39 court forms** in `src/data/forms.json`, generated by `npm run port-forms` from reference
  data. Don't edit this file by hand: change the generator and re-run it.
- **Thirteen Additional Templates** of our own in `src/data/extra-forms.ts` (petitions, a motion,
  interrogatories, a subpoena, a service agreement, the four Firm Letters and three Judge templates), edited directly.
- **Judge** (LP-90): Ruling on Motion, Sentencing Order and Warrant Decision, the judge-side forms
  `forms.json` didn't already have (it has the general Order Decree, the judgements and the
  schedules). Posted to the forum, so unbranded. The judge's name, title and signature fill from
  the active character; their court line is a `Court name` field, which a case loaded from the case
  bar fills from the case's court (`docketToForm`; no other form has that label). They use an
  `Order date`, so saving one to the Case File leaves the case's filed date alone. The Sentencing
  Order's custody, fine, restitution, community service and probation are optional sections.
- **Firm Letters** (LP-9): Engagement Letter, Retainer Agreement, Demand Letter and Letter of
  Representation. Each signs off from the active character (name, title, bar number, signature)
  and carries a case number for the case bar; the Letter of Representation has both parties too.
  They use a `Letter date`, not a `Filing date`, so saving one to the Case File records no filing.
  The retainer's fees start with prefills (`{{Hourly rate=$250 per hour|…}}`), and the firm's name
  and address are plain fields: no branding, as there's no letterhead yet (LP-23).

## Token syntax

A template is the forum post's own HTML with `{{tokens}}` (engine: `src/lib/template.ts`):

| Token                                                           | Meaning                                                                                                                                                                  |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `{{Label}}`                                                     | A text field. Fields with the same label share one value.                                                                                                                |
| `{{Label\|fallback}}`                                           | Fallback HTML shown while the field is empty.                                                                                                                            |
| `{{Label:type}}`                                                | Type: `text`, `textarea`, `date`, `number`, `select`, `check`, `spoiler`, `image`, `url`, `list`, `paras`.                                                               |
| `{{Label:select:A;B;C}}`                                        | Options (select), the on/off text (check), a date format (`long`, `short`, `us`, `dmy`…), a list wrap tag or a paragraph style.                                          |
| `{{Label=prefill}}`                                             | A prefill: `today`, `today+21`, `<Other label>-2` for dates; `YY` and `<Division?CRIMINAL DIVISION=CR;…>` for text.                                                      |
| `{{@name}}` / `{{Label@title}}`                                 | Filled from the active character (`name`, `title`, `dob`, `gender`, `phone`, `address`, `occupation`, `bar`, `email`, `signature`).                                      |
| `{{Exhibits@exhibits\|<p>None.</p>}}`                           | The exhibit list of the firm case with the form's case number (LP-13): each exhibit's letter, title and link, escaped. Never typed; the fallback shows without exhibits. |
| `{{Label>strong}}`                                              | Wraps a filled value in a tag.                                                                                                                                           |
| `{{#Items\|3}} … {{/Items}}`                                    | A repeatable block (default 1 item).                                                                                                                                     |
| `{{?Optional\|off}} … {{/Optional}}`                            | An optional section (on unless `\|off`).                                                                                                                                 |
| `{{$index}}` `{{$word}}` `{{$WORD}}` `{{$letter}}` `{{$roman}}` | The item's position inside a block.                                                                                                                                      |
| `{{$roman after Items}}`                                        | The numeral after a block's last item.                                                                                                                                   |
| `{{-- Section name}}`                                           | Starts a collapsible section in the editor. Renders nothing.                                                                                                             |

Exhibit references (LP-13): when the case number is a firm case with exhibits, the multi-line
boxes (textarea, list and paras fields) get **Insert exhibit**, which stores `[Exhibit C: Title #<id>]` in the value.
Output shows it as "Exhibit C (Title)" with the exhibit's letter and title at the time, found by id,
and escaped like any other text. Templates need nothing extra for this.

Special labels:

- **`Case number`** with a prefill such as `YYSCCR00XXX` starts empty in the editor and shows the
  pattern (in-game year, courthouse, division, number) as its placeholder and blank output. A form
  with a field labelled exactly `Case number` also gets the docket bar.
- **`Courthouse`**, **`Division`**, plaintiff/defendant and filing-date labels are filled when a
  case is loaded from a docket (`docketToForm` in `src/lib/formState.ts`).

## Required fields (LP-87)

A form's `required` list names the labels that must be filled before posting. It sits beside the
template, not in it, so the token syntax, the template-safety check and the parity tests are
unaffected.

- **In the editor**, an empty required field shows a small **Required** tag by its label.
- **Copy for forum, Copy BBCode, the Discord copy buttons and Download .docx** check first. If any
  are empty, a dialog lists them (each links to its field, opening its section) with **Go back** and
  **Copy anyway** (or **Download anyway**).
- **What counts as empty:** nothing but spaces. Fields in an optional section that's switched off
  don't count; in a repeatable block each item is checked. Tick boxes are never required.
  The check is `missingRequired` in `src/lib/formState/required.ts`.
- **The court forms** get theirs from `port-forms`, by the rule in `scripts/required-fields.mjs`:
  the case number, the parties' names (plaintiff, defendant, appellant, petitioner, respondent),
  and any name or signature filled from the character. To change it, edit the rule and re-run
  `npm run port-forms`.
- **The Additional Templates** list theirs by hand (`required: [...]` in `extra-forms.ts`).
- `tests/required.test.ts` fails if a list names a label the form doesn't have, if one names a tick
  box, or if `forms.json` doesn't match the rule.

## Escaping: why user text can't become markup

`render()` passes **every value a user types through `escapeHtml`** (`&`, `<`, `>` and `"` become
entities). Only the template's own HTML is HTML; whatever someone types is always text. That's what
stops a typed `<script>`, or an `onerror=` on an image, getting into the preview or a posted filing.

- `tests/xss.test.ts` renders every field type with hostile input and checks nothing becomes markup.
- **Don't loosen escaping** to make a form work. If a field needs structure, express it in the
  template (a `list`, `paras` or wrap tag), not in the value.

### SafeHtml: the compiler checks it too (LP-5)

`src/lib/safeHtml.ts` defines `SafeHtml`: a string with a type-only brand meaning "every user value
in this was escaped". Only the renderers make it: `escapeHtml` and `render()` in `template.ts`, and
`renderDiscordHtml` in `discordPreview.ts` (each calls `trustAsSafeHtml` after escaping). The places
HTML goes require it:

- the forum preview (`OutputPaneProps.previewHtml`) and a form's output (`FormOutput`);
- the Discord preview (`DiscordPanelProps.finalHtml`);
- the clipboard (`copyRich`);
- the `.docx` request (`docxRequestBody`).

So passing a plain string to any of them is a type error, and `npm run build` fails. Anything new
that shows, copies or exports HTML should take `SafeHtml` too, and get its HTML from a renderer.
`tests/safeHtml.test.ts` fails if any other file calls `trustAsSafeHtml` or casts to `SafeHtml`, or
if a sink is loosened back to `string`.

## The template-safety check

`scripts/template-safety.mjs` checks the template HTML itself, fallbacks included. A template fails
if it has:

- a dangerous tag (`script`, `iframe`, `object`, `embed`, `style`, `link`, `meta`, `base`, `form`,
  `input`, `textarea`, `button`, `svg`, `math`);
- an event attribute (`onclick=` and so on);
- a `javascript:`, `vbscript:` or non-image `data:` URL, or any `href`/`src` that isn't `http(s)`.

`port-forms` refuses to write if any form fails, and `tests/template-safety.test.ts` runs the check on
every form, including the Additional Templates.

## Adding or changing an Additional Template

Add a `FormDef` to `src/data/extra-forms.ts`:

```ts
{
  id: "extra-my-form",              // lowercase, unique
  court: "Additional Templates",
  section: "Motions",               // sidebar sub-label
  title: "My Form",
  required: ["Case number"],        // must be filled before copying (LP-87)
  html: `<p><strong>{{Court|SAN ANDREAS COURT}}</strong></p>
<p>Case No. {{Case number|XXX}}</p>
<p>{{Body:paras|Text of the motion.}}</p>
<p>{{Filing date=today:date:long}}<br>{{@name|Your name}}, Bar No. {{@bar|__________}}</p>`,
}
```

Use FreestyleRP court names. Then run `npm test`: the template-safety, engine, BBCode, Discord and
`.docx` suites cover every form, and the Discord snapshots will need updating
(`npx vitest run -u tests/discord.test.ts`) and reviewing.

## Court names, courthouses and case numbers

`src/lib/courts.ts` is the one place for:

- **Courthouses** (`COURTHOUSES`; currently one, Superior Court, `SC`).
- **Court names** for each division, plus the appellate, supreme and general courts.
- **The case-number shape:** 2-digit in-game year + courthouse + division + number, for example
  `90SCCR00147`. Division codes (`CR`, `CC`, `TC`, `SM`) are in `DIVISION_CODES` in `dockets.ts`.

FreestyleRP has no official court details yet, so these are generic. To change them, edit
`courts.ts` and **re-run `npm run port-forms`**, because the court forms have them written in.

## Regenerating the court forms

```bash
npm run port-forms
```

`scripts/port-forms.mjs` reads the reference forms (`.agents/reference/jsa/js_forms.data.js`) and
writes `src/data/forms.json`:

1. Parses the forms as JSON (never evaluates them) and checks there are 39 with the right fields.
2. Unwraps links to the old forum hosts; the link text stays (`scripts/scrub-links.mjs`).
3. Applies FreestyleRP wording (`scripts/freestyle-wording.mjs`): court names and phrases (for
   example "Superior Court of the State of San Andreas" → "San Andreas Court"), and the reference
   forms' courthouses and case-number code → the values in `courts.ts`.
4. Works out each form's required fields (`scripts/required-fields.mjs`, see
   [Required fields](#required-fields-lp-87)).
5. Runs the template-safety check, and writes nothing if any form fails.

So `forms.json` holds exactly what gets posted; the app does no translation at run time. Run
`npm test` afterwards: a test fails if `forms.json` isn't exactly what `port-forms` would write now
(for example after changing `courts.ts` without re-running it).

## Reference data

`port-forms` and the parity tests use three files from the
[JSA Form Generator](https://forum.gta.world/en/topic/93922-court-petitions-directory/) by Awucard:
`js_template.js`, `js_bbcode.js` and `js_forms.data.js`. They have no licence, so they're kept apart
from this code, in the private repo `danieljcode/lawportal-reference` (files at its root). With
access:

```bash
git clone https://github.com/danieljcode/lawportal-reference.git .agents/reference/jsa
```

`.agents/` is gitignored, so they're never committed here. Without them, `port-forms` stops with a
message saying where to get them, and the parity suites are skipped (see [Testing](testing.md)).
